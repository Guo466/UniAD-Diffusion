## 1. 项目整体介绍

### 30 秒电梯陈述（简历/开场白版）

> 我基于开源项目 UniAD（CVPR 2023 Best Paper Candidate，端到端自动驾驶框架）做了一个
> 规划头（Planning Head）的算法改造：把原版确定性回归式的规划头替换成了基于 Flow Matching
> （Rectified Flow）的 Diffusion Transformer 生成式规划头，让模型能够建模轨迹的多模态分布，
> 而不是只输出一条确定性的均值轨迹。我在 mini 和 full 两个数据集规模下都做了与原版的公平对比
> 实验，深入分析了两种范式在不同训练规模下的表现差异。

### 2 分钟详细版（面试官追问"详细讲讲"时）

> UniAD 是一个把检测、跟踪、地图分割、运动预测、占用预测、规划六个任务串联在一个 Transformer
> 网络里、共享 BEV 特征、端到端联合训练的自动驾驶框架。它原本的规划头很简单，就是用一个
> Transformer Decoder 加 MLP，直接回归自车未来 3 秒的轨迹坐标，本质是一个确定性映射。
>
> 我认为这种做法有个理论局限：真实驾驶场景在很多时刻是多模态的，比如路口既可以直行也可以
> 微调转向，直接用 L2 回归损失训练容易让网络学成"平均轨迹"，尤其数据不足或场景模糊时表现
> 不稳定。所以我把它替换成了 Flow Matching 框架下的 DiT——训练时让网络学习一个从噪声到
> 真实轨迹的速度场，推理时用 Euler 法做 ODE 数值积分，从随机噪声"流动"出一条轨迹。这样
> 网络学的是条件概率分布而不是一个确定性点。
>
> 除了替换规划头本身，其余所有模块（BEVFormer、TrackHead、MotionHead、OccHead）完全不动，
> 保证是一次"即插即用"的公平实验。我先在 nuScenes mini 上跑通，DiT 全面优于原版；之后
> 迁移到服务器上用 full 数据集做 6 epoch 的对比，发现结果反转了——原版反而更好。我深入排查
> 后发现这个反转本身很有意思，背后有三层原因：训练量对生成式模型比对判别式模型影响更大、
> mini 实验中我给 DiT 用了专门调优的超参而 full 实验没有、以及碰撞后处理模块本身是为回归式
> 轨迹设计的。这个过程让我对生成式建模和判别式建模在训练动态上的差异有了更实际的理解。

## 2. UniAD 原版架构相关

### Q2.1 ⭐ UniAD 的核心设计理念是什么？和传统模块化自动驾驶 pipeline 有什么区别？

**答**：传统 pipeline 是"检测→跟踪→预测→规划"串行独立训练，每个模块只优化自己的局部指标
（检测看 mAP，预测看 minADE），这些局部最优不一定等价于最终规划任务的全局最优，
存在**目标不一致（misalignment）**问题，而且误差会逐级累积传递。

UniAD 提出 **Planning-oriented** 设计：所有任务仍然分模块（保留可解释性和监督信号），
但是：
1. 所有任务头共享同一个 BEV 特征；
2. 上游任务的 Query（而不是硬编码的检测框坐标）直接作为下游任务的输入，实现**特征级别**
   而非**结果级别**的信息传递；
3. 所有任务损失同时反向传播，下游任务（尤其是 planning）的梯度会反过来塑造上游特征，
   让检测/跟踪学到的表征天然偏向"对规划更有用"的方向。

### Q2.2 BEVFormer 是怎么把多相机图像转换成 BEV 特征的？

**答**：核心是两种 attention：
1. **Temporal Self-Attention**：让当前帧 BEV Query 去关注历史帧 BEV 特征，融合时序信息
   （处理运动、遮挡）；
2. **Spatial Cross-Attention**：BEV Query 对应到 3D 空间中一根柱子上采样多个高度的参考点，
   投影回各个相机图像平面，用 Deformable Attention 在图像特征上采样、聚合，
   把透视图特征"拉"到 BEV 空间。

### Q2.3 TrackHead 的 Query 是怎么做跨帧关联（不需要外部匹配算法）的？

**答**：UniAD 用的是 Query-based 的端到端跟踪范式（类似 MOTR）——每个 track query 
代表一个跟踪目标，帧间通过**同一个 query 向量在时序上传递**来隐式完成关联，
而不是先各帧独立检测再用匈牙利匹配算法做数据关联。新出现的目标由额外的 detection query 
捕获并"晋升"为新的 track query，消失的目标对应的 query 会被标记/丢弃。

### Q2.4 原版 PlanningHead（PlanningHeadSingleMode）的输入输出是什么？

**答**：输入是 BEV 特征 + MotionHead 产出的自车轨迹 query（`sdc_traj_query`）+ 高层驾驶指令
（直行/左转/右转，command）；通过 Transformer Decoder + MLP 输出未来 6 个时刻
（0.5s 间隔，共 3 秒）相对于当前帧的 (x, y) 坐标增量，训练用 ADE（L2）损失 + 
可选的碰撞损失（基于 occ_head 预测的占用栅格）+ 运动学损失（约束加速度/曲率合理性）。

## 3. Flow Matching / Diffusion 理论相关

### Q3.1 ⭐ 什么是 Flow Matching？和传统 Diffusion Model（DDPM）有什么区别？

**答**：两者都是生成式模型，都是学习"从简单分布（通常是高斯噪声）到目标数据分布"的映射，
但建模方式不同：

- **DDPM**：定义一个离散的马尔可夫加噪过程 `x_t = √ᾱ_t x_0 + √(1-ᾱ_t) ε`，
  训练网络预测噪声 `ε`（或 `x_0`），推理时需要沿着这个随机过程反向去噪，通常要几十到上千步；
- **Flow Matching / Rectified Flow**：直接定义一条从噪声 `x_0` 到数据 `x_1` 的
  **确定性直线路径** `x_t = (1-t) x_0 + t x_1`（也可以是别的路径，但 Rectified Flow 
  用的是直线），训练网络直接回归这条路径的**速度场** `v(x_t, t) = x_1 - x_0`
  （用简单的 MSE 损失），推理时用 ODE 数值积分（如 Euler 法）沿着学到的速度场从 `x_0` 
  积分到 `x_1`。

**核心区别**：Flow Matching 的训练目标更简单直接（直线路径的速度场是常数，学习目标不含
随机噪声的复杂时间依赖），推理时用确定性 ODE 求解，理论上路径更直、需要的积分步数更少
（几步到十几步就能达到不错的效果，DDPM 传统上要上百步，虽然后续 DDIM 等方法也把 DDPM 
推理步数降下来了，但 Flow Matching 从建模上天然更适合少步数）。

### Q3.2 ⭐ 为什么在规划任务里，Flow Matching/生成式建模比直接回归更有优势？

**答**：核心在于**多模态建模能力**。直接回归（比如 MSE/L2 损失）本质上是在学习条件分布
的**均值** `E[y|x]`——如果真实分布在某个场景下是多峰的（比如路口既可能直行也可能小幅
避让绕行），回归模型会被迫输出这些峰值的"平均"，这个平均轨迹可能压根不是一个合理的
驾驶行为（比如正好穿过障碍物之间的"空隙"）。

生成式模型学习的是完整的条件概率分布 `p(y|x)`，采样得到的是分布中的一个"合理样本"，
而不是所有可能性的平均值，因此更适合表达真实驾驶数据中固有的多模态性，
理论上能生成更符合物理约束、更少穿越障碍物的轨迹。

### Q3.3 Flow Matching 的训练损失具体怎么算？

**答**：对于一对 `(x_0, x_1)`（`x_0` 是采样的高斯噪声，`x_1` 是真实轨迹的 GT），
随机采样一个时间 `t ∈ [0,1]`，构造插值点 `x_t = (1-t)x_0 + t x_1`，
把 `x_t` 和 `t`（以及条件信息，比如 BEV 特征、agent 特征）一起输入网络，
让网络预测的向量场 `v_θ(x_t, t, context)` 去回归真实的速度 `(x_1 - x_0)`，
损失就是 `MSE(v_θ(x_t, t, context), x_1 - x_0)`。

### Q3.4 推理时的 Euler ODE 积分具体怎么做？

**答**：从 `x_0 ~ N(0, I)`（高斯噪声）出发，把 `[0, 1]` 时间区间等分成 `N` 步
（比如 `sample_steps=5`），每一步用当前网络预测的速度做一阶欧拉更新：
`x_{t+Δt} = x_t + v_θ(x_t, t, context) · Δt`，迭代 `N` 次后得到 `x_1`，
即最终生成的轨迹。步数越多，数值积分误差越小，但推理耗时也越长。

## 4. DiT 架构与工程实现相关

### Q4.1 DiT（Diffusion Transformer）和 U-Net 结构的 Diffusion 模型有什么区别？

**答**：传统 Diffusion（如 DDPM 在图像上的经典实现）通常用 U-Net 作为噪声预测网络，
依赖卷积的空间归纳偏置和多尺度下采样/上采样结构。DiT 用纯 Transformer 替代 U-Net，
把输入（这里是轨迹点序列/latent）当作 token 序列处理，用 self-attention 聚合全局信息，
时间步 `t` 的条件信息通常通过 **AdaLN-Zero**（Adaptive Layer Norm，零初始化）方式
注入到每个 Transformer block，而不是像 U-Net 那样通过通道拼接。DiT 的优势是可扩展性好、
更容易利用 Transformer 生态的优化技巧，在图像生成（如 Stable Diffusion 3、Sora 底层架构）
中已被广泛验证。

### Q4.2 ⭐ 在这个项目里，DiT 是如何接入 UniAD 已有的 BEV 特征和 agent 特征的？

**答**：`DiffusionPlanningHead` 设计了几个桥接模块：
1. **BEV context tokens**：把 200×200 的 BEV 特征降采样/池化到一个较小的 token 集合
   （比如 8×8=64 个 token），作为 DiT 的条件输入之一，让轨迹生成能感知周围环境；
2. **Agent 特征**：从 TrackHead 的 900 个 query 里取最活跃的若干个（如 `max_agents=50`）
   代表周围交通参与者，同样作为条件；
3. **Ego 状态桥接**：MotionHead 产出的自车 query 通过一个小的 adapter 网络接入；
4. 这些条件信息通过 AdaLN-Zero 或 cross-attention 的方式注入到 DiT 的每个 block 中，
   与时间步 `t` 的 embedding 一起调制网络的中间激活。

### Q4.3 为什么要加 ADE 辅助损失（`ade_loss_weight`），Flow Matching loss 不够吗？

**答**：纯 Flow Matching 损失优化的是速度场的局部准确性，训练早期/数据不足时收敛较慢，
且不直接约束"积分出来的最终轨迹"与 GT 的距离。加一个辅助的 ADE（L2）损失，
对训练过程中采样出的（或直接从速度场推算的）轨迹端点做直接的距离约束，
可以加速收敛、提供更直接的监督信号，尤其在数据量有限时有帮助。这是很多
diffusion policy 类工作里常见的做法（辅助损失 + 主生成损失联合训练）。

### Q4.4 训练时为什么要做梯度检查点（gradient checkpointing）等显存优化？

**答**：这是笔记本 8GB 显存环境下的工程约束，不是算法必需。DiT 相比原版回归头引入了
更多参数（4 层 Transformer block）且训练时需要额外做一次 ODE 采样计算碰撞损失，
显存压力更大。用到的具体手段包括：降低 `queue_length`（不缓存历史帧）、
减少 `num_query`、禁用 `occ_head`、缩小 `dit_depth/dit_heads`、
关闭 BEV Adapter 等，这些都是"在满足实验能跑通"前提下的资源妥协，
在服务器满显存环境下都已经恢复为完整规模。

## 5. 实验设计与对比方法论相关

### Q5.1 ⭐ 你是如何保证 DiT 和原版 UniAD 的对比是公平的？

**答**：核心是**控制变量法**——除了 `planning_head` 的类型（`PlanningHeadSingleMode` vs
`DiffusionPlanningHead`），其余所有配置尽量保持一致：相同起点权重
（`uniad_base_track_map.pth`）、相同数据集切分、相同训练 epoch 数、相同的
BEVFormer/TrackHead/SegHead/MotionHead/OccHead 结构。

更重要的是，我做了一个**验证性检查**：对比了两个模型在 det/motion/occ 三个
**不受 planning_head 影响**的分支上的指标，发现它们高度接近（mAP 差 0.0088，
NDS 差 0.0070，属正常训练随机性范围）。这说明整个训练流程、数据处理确实是对齐的，
Planning 指标上的差异可以归因于规划头本身的设计差异，而不是实验流程的系统性偏差。

### Q5.2 你在评测过程中发现并修复了哪个"不公平"的问题？

**答**：发现评测时 baseline 默认开启了 `use_col_optim=True`（推理后用 CasADi 
非线性优化器对轨迹做碰撞规避的后处理修正），而 DiT 版本当时是 `False`
（因为 `DiffusionPlanningHead` 还没实现这个后处理接口）。这意味着 baseline 的输出
经过了额外的安全性修正，DiT 是"裸模型输出"，直接对比不公平。

我在 `DiffusionPlanningHead` 里补齐了与原版完全相同的 `collision_optimization` 
方法，并把配置里的 `use_col_optim` 也设为 `True`，保证两者在完全相同的后处理条件下
评测。修复前 DiT 在 0.5s 时刻看起来比 baseline 略优，修复后这个"优势"消失了
（甚至变差），说明修复前的结论是有偏差的，这次修复对得出可信结论非常关键。

### Q5.3 除了 L2 和碰撞率，UniAD 评测规划任务还看什么指标？为什么？

**答**：主要是 **L2 误差**（预测轨迹与 GT 轨迹在 0.5s~3.0s 六个时刻的欧氏距离，
反映轨迹精度）和**碰撞率**（`obj_col`：轨迹点是否落入障碍物包围盒内；
`obj_box_col`：考虑自车真实车身尺寸后是否会发生碰撞，更严格、更贴近实际安全性）。
两者要结合起来看，因为单看 L2 不能反映轨迹是否安全——一条 L2 很小但穿过了障碍物的
轨迹在实际驾驶中是不可接受的。

## 6. Mini vs Full 反转现象相关（重点，体现分析深度）

### Q6.1 ⭐⭐⭐ 你的实验里 mini 数据集 DiT 更好，但 full 数据集反而变差，怎么解释？

这是最容易被深挖的问题，建议按"现象 → 排除干扰 → 分层归因 → 下一步验证"的逻辑组织回答：

**答**：

**第一步，先确认这不是实验流程的问题**：我先检查了 det/motion/occ 三个不受 planning_head
影响的分支，两次实验里这些指标都基本持平，排除了"数据处理/训练流程本身出错"的可能，
说明反转确实反映的是 planning_head 本身在不同数据规模/训练量下的真实表现差异。

**第二步，分析训练范式的本质差异**：原版是判别式回归，直接学一个确定性映射，
收敛所需的有效梯度更新次数较少；DiT 是生成式建模，需要学习一个连续时间的速度场，
本质上是更复杂的学习任务，需要更多训练量才能充分收敛。full 数据集实验只跑了 6 epoch
（论文默认 20 epoch 的 30%），这个训练量对判别式回归头可能已经够用，但对生成式模型
明显不足，导致 DiT 处于欠拟合状态，且误差会随着预测时长（0.5s→3.0s）累积放大——
这正好和我实际观测到的现象一致：DiT 在 full 上的 L2 差距随时间点后移逐渐扩大。

**第三步，反过来解释 mini 上为什么 DiT 反而更好**：mini 数据集本身只有约 700 帧训练数据，
20 epoch 下两个模型其实**都没有真正收敛**（两者绝对 L2 误差都在 3~4m 量级，
是 full 数据下的 4~5 倍）。在"双方都欠拟合"的情况下，DiT 从随机噪声出发做 ODE 积分
生成轨迹的过程，天然带有一定的平滑先验，比回归头在数据严重不足时容易学出的
"扭曲均值轨迹"更稳健。所以 mini 上 DiT 的领先，某种程度上是数据极度稀缺时
生成式先验的优势，而不是真正学到了精确的分布，这个优势在数据/训练量都充分之后
不一定还成立。

**第四步，我还发现了一个容易被忽略的因素**：mini 实验里我给 DiT 用的是专门调优过的
超参（学习率 2e-5，是原版的 1/5；梯度裁剪 max_norm=5，比默认的 35 严格得多；
还降低了 motion 分支的 loss 权重防止梯度压制），这是因为 8GB 笔记本显存 + 极小数据下
DiT 训练本身不稳定，需要这些调整来防止发散。但 full 实验为了保证和 baseline
"除 planning_head 外完全一致"的实验设计原则，DiT 被迫直接套用了和原版相同的
激进学习率（2e-4）和宽松的梯度裁剪，这对本身收敛更敏感的生成式模型可能是不利的，
6 epoch 的短训练周期内可能还没能稳定下来。

**结论**：反转的根本原因是训练量不足叠加了超参未针对生成式模型适配，
mini 上的领先某种程度上是"数据不足条件下生成式先验优势"和"专门调参"两个因素
共同作用的结果，这个优势没有在更充分训练的条件下被验证。

### Q6.2 如果要验证"训练量不足"这个假设，你会怎么设计实验？成本最低的验证方式是什么？

**答**：最直接的方式是把 full 数据集训练 epoch 从 6 提升到接近论文默认的 20，
但这个成本很高（我们只有 2 张 4090，6 epoch 已经跑了约 5 天，20 epoch 预计要
15~17 天），性价比不高。

所以我先做了一个**成本几乎为零的替代验证**：既然 Flow Matching 理论上训练和推理的
积分步数是解耦的（训练学的是连续时间速度场，推理步数只影响数值积分的离散化误差），
我直接复用已经训练好的 `epoch_6.pth`，只在推理阶段把 Euler ODE 积分步数从 5 
提高到 10、20，不需要重新训练，一次评测几分钟就能跑完。如果增加步数后指标有明显改善，
说明瓶颈部分在于推理阶段的积分精度不够；如果几乎不变，则进一步支持"瓶颈在训练阶段
本身收敛不充分"，而不是推理超参的问题。这是用最低成本先排除一个变量，
再决定是否值得投入更高成本（重新训练）去验证核心假设。

### Q6.3 除了增加 epoch，还有什么低成本的方式能验证"超参未适配"这个假设？

**答**：可以只调整学习率和梯度裁剪，在同样 6 epoch 的预算下重跑一次（不需要增加训练时长，
只是换一组超参），比如把学习率降到 5e-5、梯度裁剪收紧到 10~15、
适当降低 motion loss 权重，参考 mini 版本 DiT 的调参思路。如果这样重跑后 DiT 
在相同 6 epoch 下有明显改善（哪怕没有反超 baseline），也能验证"超参未适配"
确实是加剧因素之一。这个成本和原来的训练一样（6 epoch），
但至少能获得一个独立的证据支撑归因分析。

## 7. 工程踩坑与调试相关

> 这类问题考察的是工程 debug 能力，回答时按"现象 → 定位 → 根因 → 修复"讲清楚。

### Q7.1 训练中遇到过 DDP（多卡分布式）相关的 bug 吗？

**答**：遇到过 `AssertionError: loss log variables are different across GPUs!`。
根因是 `DiffusionPlanningHead` 的 loss 字典里有些 key 是条件性生成的（比如某些
异常情况下会提前 return，跳过某个 loss 项的计算），导致不同 GPU 进程上某个 iteration
计算出的 loss 字典 key 集合不完全一致，而 DDP/MMDetection 的日志同步机制要求所有
进程的 loss key 必须完全对齐才能做 all-reduce。修复方式是在所有可能的 return 路径上
统一预先初始化好全部可能出现的 loss key（用 0 占位），保证不管走哪条分支，
返回的字典结构都是一致的。

### Q7.2 遇到过 Shapely 库相关的报错吗？怎么解决的？

**答**：遇到过 `TypeError: 'MultiPolygon' object is not iterable`（以及 
`MultiLineString` 同理）。这是 Shapely 2.0 版本的一个 API 变化——旧版本
`MultiPolygon`/`MultiLineString` 对象本身可以直接迭代得到子几何体，
新版本需要显式通过 `.geoms` 属性来迭代。定位到 nuScenes 地图 API（`map_api.py`）
里有几处旧写法的迭代代码，改成 `for geom in multi_polygon.geoms` 的形式即可修复，
属于第三方库版本兼容性问题。

### Q7.3 训练早期遇到过 loss 为 NaN / grad_norm 爆炸的问题吗？

**答**：mini 数据集小显存环境下遇到过。定位过程是：打印各个任务头的 loss 量级，
发现 motion head 的回归损失（`l_reg`）量级远超其他任务头（约 100+，而 track/map
只有个位数），在总 loss 里占主导地位，导致反向传播时梯度被 motion head "主导"，
叠加 DiT 早期参数对大学习率敏感，一步大梯度更新就可能把参数推到数值不稳定的区域。
修复方式：降低 `motion` 分支在总 loss 里的权重（`task_loss_weight`），
同时调小学习率、收紧梯度裁剪阈值，多管齐下让训练在早期阶段更稳定。

## 8. 追问 / 深挖方向预案

面试官可能会针对"薄弱环节"继续追问，以下是几个高概率追问方向和应对思路：

**Q: 你觉得这个改进真的有价值吗？现在的结果 full 上还打不过 baseline。**

> 诚实回答，同时把结论转正：目前受限于训练资源（6 epoch vs 论文默认 20 epoch），
> 还没能在 full 数据集规模下验证 DiT 的优势，但整个实验过程本身验证了：
> (1) 生成式规划头在工程上可以完整替换进 UniAD 这样复杂的多任务框架并跑通训练/推理全流程；
> (2) 通过控制变量对比，能够严谨地定位不同训练规模下两种范式表现差异的具体原因；
> (3) 给出了后续验证方向（增加训练量、调整超参、优化后处理）。这是一个有严谨方法论支撑的
> 阶段性结论，而不是"做完就结束"的项目。

**Q: 如果只能选一个方向继续优化，你会选哪个？**

> 我会优先选"针对 DiT 单独调参后在相同 6 epoch 预算下重跑"，而不是直接加 epoch。
> 因为这个成本和之前一样（不增加训练时长），却能独立验证"超参未适配"这个假设，
> 性价比最高；如果调参后仍然明显落后，再考虑是否值得投入更高成本去增加训练轮次。

**Q: 你怎么知道 DiT 没有训崩，而只是没训好？**

> 通过检查检测/运动预测/占用预测三个分支的指标验证——如果 DiT 的联合训练把上游特征
> 训崩了，这些分支的指标应该会明显劣化，但实际观测到它们和 baseline 高度接近，
> 说明整个网络的联合训练是健康的，只是 planning_head 自身还没收敛到位。

**Q: Flow Matching 和普通的 VAE/GAN 做轨迹生成有什么优劣？**

> VAE 训练稳定但生成质量/多样性通常不如扩散类方法，容易出现后验坍缩；
> GAN 生成质量可以很好但训练不稳定（模式坍缩、对抗训练难调）；
> Flow Matching/Diffusion 训练目标简单（回归损失，无对抗），训练稳定性好，
> 生成质量和多样性通常优于 VAE，代价是推理需要多步迭代（虽然 Flow Matching
> 已经比传统 Diffusion 少很多步）。在轨迹规划这种低维（几维坐标 × 几个时间步）、
> 对实时性有一定要求的场景下，Flow Matching 的"训练稳定 + 少步推理"的组合是比较
> 合适的折中选择。
